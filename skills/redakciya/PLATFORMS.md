# Площадки

Режим площадки — `platforms.<ключ>.mode` в `config.yaml`. Секреты — файлы в `~/.config/redakciya/`
(Windows: `%USERPROFILE%\.config\redakciya\`), в config только их имена. Браузерные режимы работают в отдельном
профиле браузера публикатора (`~/.config/redakciya/chrome`; Google Chrome, на Windows без него — Microsoft Edge):
основной браузер автора не трогается, вход делает сам автор через `rk login <ключ>`. В этом профиле живут вошедшие
сессии Telegram, VK, X — его нельзя копировать, отправлять кому-то или в поддержку; на другом компьютере — `rk login` заново. Проверка всех входов — `rk check`
(для браузерных площадок он открывает страницу публикации и ждёт поле ввода).

**Бета-площадка выходит первый раз** — одной новостью: пакет из одной строки в `order.txt`,
`rk publish <пакет> --only <ключ>`, проверка глазами, потом весь пакет.

Статус: **проверено** — режим работал на живых каналах; **бета** — написан по живой странице, но полная выкладка
ещё не прогонялась: первый раз запускай с `--dry` и смотри снимок.

## Telegram — `tg`

| Режим | Что нужно | Ограничения |
|---|---|---|
| `web` (по умолчанию, проверено) | `rk login tg` → вход по QR в Telegram Web | альбом до 10 файлов, подпись до 4096 знаков с Premium (1024 без него) |
| `telethon` | `api_id`/`api_hash` с my.telegram.org → `~/.config/redakciya/tg_api.json` `{"api_id": …, "api_hash": "…"}`, потом `rk login tg` (код из Telegram) | то же; движок с `engine[telethon]` |
| `bot` | бот от @BotFather — администратор канала; токен в `tg_bot_token` | подпись к альбому до 1024 знаков |

Поля: `channel: "@канал"` (или ссылка `https://t.me/канал`), `title_check: "часть названия"` — перед вставкой движок
сверяет название открытого чата и ничего не вставляет в чужой; `premium: true/false` — есть ли Premium у аккаунта
публикатора (без него подпись к альбому до 1024 знаков, `rk check-post` это проверяет). Канал должен быть **публичным,
с @username**: вышедший пост движок находит по ленте `t.me/s/<канал>`. Порядок: Telegram выходит после остальных
соцсетей (чтобы автор успел увидеть ошибки).

Грабли Telegram Web:
- Новый пост в **канале** уходит без пустых строк между абзацами (в «Избранном» и в поле подписи перед отправкой они
  целы). Правка поста их сохраняет — движок после выхода поста сверяет t.me и сам переписывает подпись через
  «Изменить». Если видишь ⚠ «пустые строки потерялись» — `rk tg-edit <id>:<slug>`.
- `data-mid` сообщения канала = 2³² + номер поста. Переход к посту (`#?tgaddr=…post=N`) работает только на свежей
  странице: смена адреса на открытой не прыгает.
- Ссылка с `&` на t.me показывается как `&amp;amp;` у любого канала — это вид страницы t.me, не ошибка.
  В href Telegram Web берёт адрес как есть: `&amp;` надо вернуть в `&` до вставки (движок делает).
- Пункт меню «Edit»/«Изменить» содержит символ иконки — искать по последней строке текста.
- С 14.10.2026 в Web K есть кнопка ИИ-редактора (`.chat-input-ai-editor-button`, значок «Ai»): когда в поле есть текст,
  она лежит поверх центра «Отправить»/«Сохранить», и обычный клик 30 с ждёт и падает (`Locator.click: Timeout`).
  Движок жмёт у левого края кнопки отправки, где ИИ-кнопки нет. Снова «Timeout» на отправке — сверь `elementFromPoint`
  над кнопкой: что-то новое легло сверху.

Запасной ручной путь (Web недоступен): открой канал в приложении Telegram, перетащи файлы альбома в порядке `media`,
вставь текст из `rk`-рендера (`posts/<slug>/post.md` без шапки; ссылки — через Ctrl/Cmd+K), отправь,
впиши адрес поста в `published.json` ключом `tg`. Ничего не печатай в поле чата, пока не убедился, что открыт канал.

## MAX — `max` (проверено)

Бот MAX: создайте у @MasterBot, токен — в `max_token`, бота — администратором канала с правом публикации.
`channel_id` — id канала (отрицательное число; `rk check` покажет название). Текст до 4000 знаков **вместе с HTML-разметкой**.
Не влезает — движок сам снимает адреса у обычных ссылок с конца (текст ссылки остаётся): сначала в теле, потом в
последнем абзаце; ссылку на чат не трогает никогда. Сколько снято — видно в `rk publish … --dry`. Не хватило и этого —
`rk check-post` скажет «даже без адресов ссылок», текст сокращает автор. Альбом фото и видео одним сообщением.

## VK — `vk` (стена сообщества)

| Режим | Что нужно | Статус |
|---|---|---|
| `api` | своё приложение VK (vk.com/editapp?act=create, Standalone) → `app_id`; ключ сообщества (Управление → Работа с API, права: управление, фото, стена) в `vk_group_token`; `rk login vk` берёт токен пользователя (живёт сутки, обновляется тем же `rk login vk`) | проверено |
| `web` | вход в профиле публикатора (`rk login vk`), права редактора сообщества | проверено у автора 12–14.10.2026: фото по одному, повтор копией 1600/1280 px, если VK отбросил файл («Не удалось загрузить»); `--dry` собирает пост целиком и убирает черновик |

`group_id` — число без минуса: откройте сообщество → «Управление», в адресе будет `vk.com/club<число>?act=edit`; или в
адресе любого поста сообщества `wall-<число>_<номер>`. Для `web` задайте ещё `title_check` — часть названия сообщества:
движок сверит заголовок страницы, прежде чем что-то вставить (иначе неверный номер уведёт пост в чужую группу).

Ключ сообщества не загружает фото и видео — для этого и нужен токен пользователя. VK иногда отдаёт пустой ответ
загрузки фото — движок повторяет **не больше 3 раз** (последний — копией 1600 px) с паузой. Не встало — пост не выходит,
а API-загрузка выключается на 3 часа (отметка `<дом>/.vk_api_down`): остальные новости пакета сразу идут через браузер
(как `web`; нужен вход в VK в профиле публикатора — `rk login vk`). Почему так: 12.10.2026 у автора 5–12 повторов на
каждое фото в десятках постов VK счёл флудом — загрузка по API встала совсем, а браузер в том же аккаунте работал.
Без браузерного запасного пути — `fallback: none` в `platforms.vk`: тогда хвост пакета ждёт, `rk publish <пакет> --only vk`
через 3 часа. Отметку удаляют руками, только если VK точно ожил. Ссылки — текстом «текст (url)».

Токен пользователя живёт сутки: длинный пакет начинайте со свежего (`rk login vk` прямо перед `rk publish`) — 11.10.2026
у автора токен, взятый «если истёк», кончился посреди пакета, и последние посты ушли без части фото.

Запасной ручной путь (`web` сломался): откройте сообщество, «Создать» → «Пост», перетащите файлы альбома в порядке
`media`, вставьте текст из `post.md` без шапки, заменив `[текст](url)` на «текст (url)» и убрав `**`, опубликуйте и впишите
адрес поста в `published.json` ключом `vk`.

## VK-канал — `vkch` (проверено)

Канал в мессенджере VK: `url: "https://vk.com/im/channels/-<id>"`, вход в профиле публикатора. Пакет идёт в обратном
порядке (`reverse_order`), чтобы первая новость пакета оказалась сверху. Отрицательный `cmid` в ответе = откат
сообщения сервером: движок считает выкладку неудачной.

## Facebook — `fb` (страница, Graph API)

Только страница — в личный профиль API не публикует. Один раз:
1. developers.facebook.com → «Мои приложения» → приложение (можно то же, что для Threads) → сценарий
   «Управление всем на странице».
2. App ID и App Secret → `fb_app.json` `{"app_id": "…", "app_secret": "…"}`.
3. Graph API Explorer → «Get User Access Token» с правами `pages_show_list`, `pages_read_engagement`,
   `pages_manage_posts` → токен в файл `fb_user_token`.
4. `rk login fb` — обменяет на бессрочный токен страницы (`fb_page_token`). `page_id` — в config.

Альбом: фото загружаются без публикации и выходят одним постом. Видео в альбом с фото не встаёт — если есть фото,
выйдут только они; если только видео — выйдет первое. Текст — как в VK, ссылки в скобках. Из России Graph API
доступен только через VPN. Версия API — `api_version` (по умолчанию `v24.0`).

## Threads — `threads`

| Режим | Что нужно | Статус |
|---|---|---|
| `api` | токен Threads (Meta) в `threads_token` (живёт 60 дней, движок продлевает его сам раз в неделю), картинки — по публичным адресам: загружаются на сайт автора | проверено |
| `web` | вход в профиле публикатора (`rk login threads`) | бета |

Текст — `threads.txt` до 500 знаков, `{LINK}` → ссылка на запись сайта или пост Telegram, поэтому Threads идёт после них.
Грабли: загрузка картинок по SSH без таймаута может висеть бесконечно — движок ставит таймауты.

## X — `x` (проверено)

Вход в профиле публикатора. `x.txt` до 280 знаков, ссылка считается за 23. Лента профиля запаздывает и иногда отдаёт
соседний твит — адрес твита движок сверяет по тексту, а не по «последнему в ленте».

## YouTube — `yt` (проверено)

Записи сообщества на канале: вход владельца канала в профиле публикатора. YouTube отвергает всю пачку, если хоть
одна картинка уже 2:5 или шире 5:2 — такие кадры движок пропускает и пишет об этом.

## Дзен — `dzen`

| Режим | Что нужно | Статус |
|---|---|---|
| `tg_import` | Дзен Студия → настройки канала → «Импорт из Telegram» (один раз) — Дзен забирает посты сам | проверено |
| `web` | вход в профиле публикатора (`rk login dzen`) | бета |

При импорте заголовок режется по первой запятой — поэтому в WRITING.md заголовок без запятых.

## Свой сайт — `site`

| Режим | Что нужно |
|---|---|
| `api` | адрес API (`url`) и ключ в `site_key`. Протокол ниже, образец приёмника — `engine/examples/site_api_receiver.php` |
| `wordpress` | адрес сайта, пользователь (`user`) и пароль приложения WordPress (Профиль → Пароли приложений) в `wp_app_password`; `category_ids`, `status` (`publish`/`draft`) |

Протокол `api`:
```
POST <url>   Authorization: Bearer <ключ>   multipart/form-data
  title, html, excerpt, slug, tags[], categories[], published_at (необяз.), media[] (по порядку альбома; первый — обложка)
→ 201 {"id": "...", "url": "https://.../news/slug"}    повтор с тем же slug → 200 и тот же id
GET <url>/<id> → 200 {"id", "url", "title"}            GET <url>/ping → 200
```
Сайт выходит сразу после Telegram: Threads и X берут ссылку на запись сайта.

## Общие грабли браузерных режимов

- Профиль Chrome публикатора нельзя открыть двумя процессами: «профиль занят» — закройте окно публикатора (Cmd+Q)
  или дождитесь конца `rk publish`.
- `connect_over_cdp` к окну профиля, запущенному с `--remote-debugging-port`, зависает после подключения — движок
  всегда запускает свой экземпляр (`launch_persistent_context`).
- Сбой — снимок страницы в `posts/<slug>/.web-<ключ>.png`. Смотри его, прежде чем повторять.
- «Кнопка нажата, но проверка не прошла» — не повторяй вслепую: проверь площадку глазами, иначе выйдет дубль.
- Проверки на бота и капчи движок не проходит и обходить не пытается: войдите сами в окне `rk login`.
